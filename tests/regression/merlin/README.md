# Merlin Regression Tests

This directory contains regression tests for Merlin syntax assembly, ensuring that bug fixes remain stable across releases.

## Test Files

### branch_relaxation.asm
**Bug Fixed:** Commit c9c3371 - Branch relaxation algorithm
**Issue:** Branch relaxation incorrectly used "start long, shrink" algorithm which inflated addresses in pass 1, causing branches that could fit SHORT in the true minimal layout to appear out of range and get unnecessarily expanded.
**Fix:** Changed to "start short, expand only when necessary" algorithm which produces minimal expansions.

**Test Coverage:**
- Three sequential short branches to same forward target (validates minimal expansion)
- Branch just within range (+127 bytes)
- Branch just out of range (+128 bytes, requires expansion)
- Multiple branches with mixed distances
- Backward branches (negative offsets)

**Assembly:** Requires `--relax-branches` flag

**Classic Counterexample:**
```asm
BCC TARGET    ; \
BCS TARGET    ;  } All to same target
BEQ TARGET    ; /
NOP
NOP
NOP
TARGET RTS
```
- Start-long: Inflates all → all appear long → 9 bytes (WRONG)
- Start-short: Tries all short → all fit → 6 bytes (CORRECT)

### variable_scoping.asm
**Bug Fixed:** Commit 4f869c3 - ]variable unique instance naming
**Issue:** ]variables were not generating unique instance names during multi-pass assembly, causing forward-reference resolution to fail.
**Fix:** Implemented GenerateVariableInstanceName() which creates unique names like "]varname##N" where N is the instance counter.

**Test Coverage:**
- Basic ]variable definition and use
- ]variable reassignment (creates new instances)
- Multiple ]variables with different scopes
- ]variables in expressions
- Forward references with ]variables (critical test case)
- ]variable scope rules (should NOT anchor local label scope)

**Key Behavior:**
- Each ]variable assignment creates a unique instance
- ]variables do NOT anchor local label scope (only non-':' and non-']' labels do)
- Forward references must work correctly with instance naming

### rw18_header.asm
**Feature Added:** Commit 4f869c3 - --rw18 USR header generation
**Purpose:** Adds Merlin/Prince of Persia compatibility by prepending a 12-byte RW18 header to binary output.

**Header Format:**
```
Offset  Size  Content
------  ----  -------
0x00    4     Magic: "USR\x1a" (0x55 0x53 0x52 0x1a)
0x04    2     USR arg1 (uint16_t, little-endian)
0x06    2     USR arg2 (uint16_t, little-endian)
0x08    2     USR arg3 (uint16_t, little-endian)
0x0A    2     USR arg4 (uint16_t, little-endian)
```

**Test Coverage:**
- USR directive with four arguments: `USR $0300,$8000,$0800,$0000`
- Validates header structure in binary output
- Simple test program following header

**Assembly:** Requires `--rw18` flag

**Example Output:**
```
00000000: 55 53 52 1a 00 03 00 80  |USR.........
00000008: 00 08 00 00 a9 42 8d 00  |.........B..
         └─────┬─────┘└──program──
              USR args
```

### immediate_symbol_ref.asm
**Bug Fixed:** Expression evaluator handling of immediate mode with symbol references
**Issue:** Expression evaluator failed with "stoul: no conversion" when immediate mode referenced symbols.
**Pattern:** Common in Prince of Persia source: `POPside1 = $a9` then `lda #POPside1`

**Test Coverage:**
- Immediate mode with EQU constants
- Immediate mode with math expressions
- Immediate mode with forward references

## Running Tests

Run all Merlin tests:
```bash
cd tests/regression
python3 run_regression.py --all
```

Run specific test:
```bash
python3 run_regression.py merlin/branch_relaxation.asm
```

Run with verbose output:
```bash
python3 run_regression.py --all --verbose
```

## Test Metadata

Each test file includes metadata in header comments:

```asm
* Test: Test Name
* Syntax: merlin
* CPU: 6502
* Flags: --relax-branches --rw18
```

The test runner parses this metadata to automatically configure assembly options.

## Expected Binaries

Golden binaries are stored in `merlin/expected/`:
- `branch_relaxation.bin` - Assembled with `--relax-branches`
- `variable_scoping.bin` - Standard assembly
- `rw18_header.bin` - Assembled with `--rw18`
- `immediate_symbol_ref.bin` - Standard assembly

These are generated by xasm++ itself and serve as reference for byte-for-byte comparison.

## Adding New Tests

1. Create `.asm` file in `merlin/` directory
2. Add metadata in header comments (Syntax, CPU, Flags)
3. Assemble with xasm++ to generate golden binary:
   ```bash
   xasm++ --syntax merlin --cpu 6502 [flags] -o merlin/expected/test.bin merlin/test.asm
   ```
4. Run regression test to verify:
   ```bash
   python3 run_regression.py merlin/test.asm
   ```
