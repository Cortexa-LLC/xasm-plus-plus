-------------------

✓ "*+4"    → "32768+4"    → 32772
✓ "*-2"    → "32768-2"    → 32766
✓ "*+$10"  → "32768+$10"  → 32784
✓ "*&$FF"  → "32768&$FF"  → 0

✓ "*<4"    → "32768<4"    → true (comparison)
✓ "*"      → existing code handles this

❓ "**4"   → Falls through (ambiguous: *×4 or * with *4?)
❓ "*2"    → Falls through (is this *×2 or label *2?)


ALTERNATIVES REJECTED:
----------------------

Option 1: String replacement (complex heuristics)
  - Must distinguish * as operator vs current address
  - Fragile with edge cases like "2**+4"

Option 2: Modify ExpressionParser (too broad)
  - Changes shared code used by all syntaxes
  - Might break CA65, other assemblers
  - Larger scope than needed


WHY THIS FIX WORKS:
-------------------

1. Minimal scope - only touches SCMASM syntax
2. Simple logic - lookahead 1 character
3. Leverages existing code - ParseExpression does the work
4. No string manipulation tricks
5. Handles all common cases
6. No changes to shared ExpressionParser
